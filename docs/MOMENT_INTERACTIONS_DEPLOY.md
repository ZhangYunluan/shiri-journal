# 0.8.1 互动与审核更新

## 仅点赞需要增量 SQL
前提：现有 001、002、004 已部署。登录腾讯云控制台 → CloudBase → 现有环境 → 数据库 → PostgreSQL → SQL 编辑器，审阅并执行 `cloudbase/migrations/005_moment_interactions.sql`，再执行 `verify_moment_interactions.sql`，各项应为 true。本次未替你执行；不要重跑旧迁移或改动 shiri-media。

新增一张点赞表和私有限流表、独立 `shiri_interactions` RPC。主键 `(record_id,user_id)` 防重复；每次显式设为赞或取消赞，重复请求不重复写入。实际状态变更最多每人 60 次/分钟、500 次/天。直连表权限撤销且开启 RLS，公开 RPC 仅 authenticated 可调用，身份取 auth.uid。聚合辅助函数不开放给客户端。

评论仍用原 `shiri_comments`，仅主人与该参与者可见。评论数字表示**自己有权看的留言**，不会暴露另一位好友的私密线程数量；赞只公开合计，不返回点赞者名单。撤销授权、屏蔽、删除关系、收回片刻均重新校验。无需新云函数、密钥、地图或付费 API。未部署 005 时不伪造点赞成功，原评论仍可用。

## 媒体位置与原图
- 新增可选 `ACCESS_MEDIA_LOCATION`，仅点击“更多细节 → 读取原图地点”时请求；授权后自动采集可复用权限读取历史照片 EXIF。拒绝/没有 GPS 时可继续保存。没有实时位置、后台定位、全文件管理或写相册权限。
- JPEG/PNG/WebP 中存在可解析 EXIF 时本地直接填坐标；原生读取用已有 MediaStore 来源及 ExifInterface。没有地名反向解析，不猜测地名。原地点可编辑/清除，地点不进入现有云端投影，上传照片仍重新编码去除 EXIF。
- 原图删除只在首次审核的批量“移除选中”中出现。默认仅排除，可撤销；选择系统删除会提示数量并进入 Android 系统确认。Android 11+ 使用 createDeleteRequest + Activity Result，不采用静默降级。
- 只删除队列中可验证的媒体 URI：校验媒体版本、生成编号和当前原图 SHA-256，禁止任意路径/URI。已保存记录关联资产受保护；其他账号已有该来源时保守拒绝。
- 历史索引不完整、经系统转码后无法与原图逐字节核验、手动网页选图未获得原始 URI、权限不足等情况，保留原图并明确失败，可仅排除；不会通过文件名匹配猜测。Android 10 及以下请使用系统相册删除。
- 取消系统确认不改变审核列表；仅系统确认且再次查询确认已移除的项写入排除状态。失败项保留可重试；撤销排除只能恢复拾日副本，**不能恢复已删除的系统原图**。系统删完时进程被杀/本地提交失败，无法确认的项仍留在审核中供核对，不误报成功。

## 验收与回滚
保留原包名/原签名，versionCode 27。先在 APP 导出备份，再覆盖安装，禁止先卸载或清除数据。真机重点验证不同 Android 版本/部分照片授权、键盘、取消与批量删除、升级数据，以及真实 A/B/C 评论/赞和撤权场景。自动化使用合成响应与本地 PostgreSQL，不代表生产验收。

停用点赞可撤销 authenticated 对新 RPC 的 EXECUTE 权限，不删除数据；客户端刷新检测后禁用点赞，原评论和媒体接口保留。不要为回退卸载 APP 或删除新旧表。
