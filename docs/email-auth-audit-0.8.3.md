# 邮箱认证排查 0.8.3

2026-11-06，基于团队提交 b1cb1b5。用户本轮选择先做本地排查。所有复现使用合成地址和拦截的认证响应。

## 反馈核实

“邮箱不区分大小写导致重复账号或额度滥用”未复现。本轮缺少受控真实邮箱，尚无 CloudBase 实际 UID、发码限频或跨邮箱验证码复用的云端验证结果。已查阅的 HTTP 文档说明验证码挑战与验证凭据流程，尚未找到可直接据以修改用户名部分大小写的服务约定。

现有客户端空间经官方 user/me 验证后以 sub 编码，来源为 localCloudSpace(uid)。业务资料的主键为 user_id，shiri_social 从 auth.uid() 获取身份并使用事务锁及 ON CONFLICT。AI 云函数先验证 user/me，再以 sub 预留额度，限额表以 UID 与日期联合约束。邮箱输入的大小写不会在这些项目代码中直接生成新身份。生产服务对不同写法实际分配何种 UID 仍需受控验证。

当前 CloudBase 客户端使用邮箱验证码，密码登录和邮箱绑定尚无该客户端入口。本次修复集中在发码、校验及状态回写。

## 已确认并修复

- 在同一认证实例并发调用时，旧代码可发出两个发码或校验请求。统一的处理中标志现在覆盖完整发码及验证登录流程，退出时的代数校验阻止旧响应恢复挑战或继续过时登录。
- API 层原先未处理两端空白，页面仅自行 trim。现在由认证入口统一去除空白并小写域名，挑战、注册和页面显示复用同一地址。用户名部分的大小写、点号和加号标签按原样传递。
- 官方 rate_limit_exceeded 在 HTTP 400 且未附描述时，旧页面仅显示通用错误。现在明确提示频繁操作，并识别人机验证、验证码错误和过期结果。

这些客户端修复控制本应用的请求与状态。服务器有效限频须由 CloudBase 实际执行并通过云端验收。

## 验证范围

回归测试先在旧实现观察失败，再用于验证修复。覆盖并发发码、首次注册与老账号并发校验、校验时换邮箱、退出与晚到响应、空白/大小写/点号/标签、错误与过期、限频及人机验证错误。浏览器使用实际页面和合成后端，验证重复点击、规范化地址展示，以及同一服务端 UID 下历史记录与好友列表的恢复。

相关复盘、好友 RLS 和 AI 额度测试复用现有本地测试。源码安全检查与 APK 签名检查纳入交付。Android 真机、真实邮箱服务和生产账号验收留待负责人安排。

本次针对性 Node 测试 55 项通过，覆盖认证、账号空间、业务资料与好友授权、AI UID 限额和分享同步。scripts/verify-email-auth.mjs 的实际页面合成回归通过，包含正常入口的重复点击、错误与过期、人机验证/限频提示，以及固定 UID 下历史记录和好友列表恢复。

## CloudBase 后续验收

负责人准备专用测试邮箱后，低频依次验证域名大小写、用户名大小写及前后空白，每次在本机输入验证码。通过身份认证用户管理与已验证的 user/me UID 比较身份，再核对业务资料数量及同一 UID 的 AI 使用量。只保存脱敏后的请求时间、错误码、UID 是否相同和计数结果，日志屏蔽邮箱、验证码与令牌。

使用两个受控邮箱验证旧请求验证码不能用于另一个 verification_id，检查错误、过期、重复校验以及正常注册/登录。邮箱实际发码限制按服务响应验收，达到限制后停止操作。若仅更换大小写获得新 UID 或新的限额，需要向 CloudBase 提交脱敏工单与频控配置检查，先由负责人审阅重复账号处理方案。

人机验证由 CloudBase 返回 captcha_required 后触发。当前客户端给出提示并停止本次流程，真正完成验证需要配置可用的官方登录页入口或进一步对接官方图形验证流程。入口配置状态尚待负责人核实。

本次代码修复无需数据库迁移或云函数部署。生产频控和人机验证配置、不同写法 UID 的实际结果均待云端验收。
