## 内测统计的边界

本 APK 的 `BETA_CONFIG.endpoint` 留空。默认关闭；明确同意后只在当前账号本机保留最近 30 天计数，最多 150 个日期/事件组合。不上传，没有统计查看接口或付费请求。可在「设置 → 帮助改善内测体验」关闭并清除。备份不携带统计和同意状态。

事件：首次保存、后续保存（批量按照片数）、进入复盘、进入好友近况、一次同步任务出现错误。编辑已确认记录不重复计保存；重复渲染页面不重复计查看。同一同步修订在当前进程只计一次错误。首次保存指本账号本机记录，不是平台注册转化；重装/换设备不能用于准确去重。仅发送版本、日期、事件名及次数，不发送照片、日记、心情、标题、ID 或原始报错。它不是完整用户追踪系统。

若将来配置新的接收地址，原本机同意自动失效，必须重新告知并取得同意。接收函数通过 [CloudBase 官方 user/me 接口](https://docs.cloudbase.net/http-api/auth/user-me) 验证当前用户 Access Token，不采用客户端 UID。匿名、失效会话、未知字段、超限请求被拒绝。每个实例按用户每分钟限一次；实例间没有统一额度。网络中断后重试可能重复计数，因此日志只能作为内测参考，不能当精确营收/留存报表。

## 需要集中查看统计时（本次未执行）

1. 腾讯云 CloudBase → `shiri-dev` → 云函数 → 新建 **HTTP Node.js 20** 函数，命名 `shiri-telemetry`。上传该新目录中的 `index.js`、`package.json` 和 `scf_bootstrap`；启动文件使用 LF 换行且设为可执行。不要覆盖 `shiri-media` 或测试函数。
2. 函数配置 → 环境变量：按同目录 `.env.example` 填入环境 ID、允许来源 `https://localhost`、CORS 所属层 `gateway`。**不需要数据库密码或 service_role。** 网关添加独立 `/shiri-telemetry` 路由；允许 POST/OPTIONS、Authorization/Content-Type，来源仅填写实际 APP/Web 来源，避免重复 CORS 响应头。
3. 云函数详情 → 日志查询：仅腾讯云主账号或具有该日志资源读取权限的管理员能看统计。不要向 APP 普通用户下发腾讯云 CAM 凭证，不配置公共日志访问。普通用户 Access Token 只能提交自身操作，GET/统计查询始终返回 405。控制台实际 IAM 隔离需部署后验证；参考 [环境级访问权限控制](https://docs.cloudbase.net/cam/access-manage) 与 [日志查询](https://docs.cloudbase.net/cloud-function/debugging/log)。
4. 确认函数日志已接入现有日志资源，保存期不超过 30 天，关闭记录 Authorization/请求正文的调试日志。网络网关自身可能保留访问元数据；上线前更新隐私告知。若控制台提示开通付费日志产品，先核算现有套餐，当前无需购买。
5. 使用测试账号验证：无 Token 401、匿名 403、合法计数 204、GET 405、额外个人资料字段 400、同一实例一分钟内重复 429。管理员日志只应出现 `shiri_beta_counts` 和白名单计数，不出现邮箱/UID/照片/Token。
6. 完成这些真实验证后，再将客户端 `BETA_CONFIG.endpoint` 配为已验证的 HTTPS 路由，重新构建并重新征得用户同意。不要仅凭路由可达就打开采集。云函数调用/日志可能消耗现有腾讯云额度；本次未产生新增第三方 AI/API 费用。
