# 0.8.0 片刻留言：仅增量部署

本地日历、每日感受、照片回顾与好友备注无需任何云端迁移。留言需要执行新增004；本次没有替你部署。

## 控制台操作
1. 打开腾讯云CloudBase控制台，选择现有shiri-dev环境（承载真实用户，先做好数据库恢复点并安排低峰）。
2. 进入数据库 → PostgreSQL → SQL编辑器，打开新查询。
3. 复制cloudbase/migrations/004_moment_comments.sql完整内容并执行。不要重跑001、002或003，不改私有照片桶/原有授权策略。
4. 成功后运行verify_moment_comments.sql，只查询结构和权限；所有ok应为true，不读取评论正文。
5. APK登录后在好友页点刷新。客户端发现shiri_comments RPC版本1后才显示“聊聊这个片刻”和“查看留言”。若函数尚未部署或不可访问，原有记录/好友继续可用，留言入口不显示。

使用已有PostgreSQL REST接口：POST /v1/rdb/rest/rpc/shiri_comments，JSON为p_action与p_payload。Authorization沿用对应用户Access Token。无需新增HTTP云函数或照片网关、无需任何新客户端Key。

## 权限与成本
新增一张公开schema业务表shiri_moment_comments（RLS开启、直接访问全部撤销）和一张shiri_private.comment_limits计数表；只通过身份验证RPC操作。
每段交流由片刻ID+具体留言好友UID隔离，其他好友即使能看同一片刻也不能读到这段交流。主人在“我的片刻 → 查看留言”选择对应参与者回复，最多展示100个近期参与者；留言按时间顺序每页30条，按需继续加载。
每次读/发都重新检查原有好友关系、屏蔽、片刻shared、分类和历史范围。撤销后拒绝后续读/发；已有下载内容不能远程抹除。自己可删除自己的留言，主人可删除自己片刻下的留言；删除自己的旧留言不要求恢复已撤销的查看权限。
单条1–300字，支持普通Emoji和换行；每人每分钟10次、每天100次，计数不因删除评论重置。重试沿用clientId，不重复插入。JSON字段白名单；身份只来自auth.uid()/auth.role()。
留言不写入个人复盘、AI摘要、内测统计或生活ZIP。页面关闭/切账号/切后台清理内存显示，403/404/401权限变化时清除当前留言及可控照片显示。
只使用现有数据库套餐中的存储/请求资源，没有新增付费AI或外部API；数据库本身仍按现有套餐计费。不自动开通或购买产品。

## 必须真实双账号验收
1. A/B成为好友并由A授权。A保存片刻自动同步，B在近况点击“聊聊这个片刻”留言。
2. A在“好友 → 我的片刻 → 查看留言”回复，B重新打开可读；C虽获同一片刻查看权限，也只能看到自己与A的交流。
3. 测试双方删除自己的留言、A删除B留言；空白、超长、连续发送需明确拒绝。
4. 断网发送保留草稿，重试不重复；不保证离线留言自动发送，避免意外发送私人话语。
5. A撤销授权/屏蔽/删除B/删除片刻后，B后续读取和发送失败；解除屏蔽不能自动恢复好友或授权。
6. 让应用在留言期间切后台，再返回刷新；重新检查权限。不使用真实私密正文做截图或日志。

## 审核与回退
先审阅004及自动化测试，再在生产执行。不需要改shiri_social的定义或照片服务。
如需暂停留言，管理员可单独REVOKE EXECUTE ON FUNCTION public.shiri_comments(text,jsonb) FROM authenticated；刷新后客户端停止显示入口，原有好友/照片不受影响。不删除表、不清空留言数据。恢复执行权限仍需负责人确认。
